# Cinema TMS Admin

이 프로그램은 TMS 클라이언트와 분리된 관리자 전용 오프라인 발급 도구입니다.

## 실행

`Cinema_Tms_Admin`은 라이선스 관리자 전용 독립 프로젝트입니다. ZIP을 완전히 압축 해제한 뒤 `deployment\Cinema-TMS-Admin.vbs`를 실행합니다.

## 발급 권한

- 프로그램과 ZIP에는 개인 서명키가 포함되지 않습니다.
- 최초 실행에서 관리자 로그인 계정을 만들고 기존 개인 서명키를 관리자 DB로 이전합니다.
- 개인 서명키는 각 `admin`·`operator` 계정 비밀번호에서 파생한 키로 AES-GCM 암호화되어 `licenses.db`에 저장됩니다.
- 비밀번호는 bcrypt로 해시하며 로그인 5회 실패 시 15분 동안 계정이 잠깁니다.
- 비밀번호 길이와 문자 조합은 강제하지 않으며 빈 비밀번호만 사용할 수 없습니다.
- `admin`은 계정 관리·발급·폐기·감사 로그, `operator`는 발급·갱신, `viewer`는 조회만 할 수 있습니다.
- 기존 비밀번호 암호화 키 또는 Windows DPAPI 키가 있으면 최초 관리자 생성 시 DB 방식으로 한 번만 이전합니다.
- 새 PC에 계정과 이전 키가 없으면 기존 `Cinema_Tms_Admin\data\licenses.db`를 복사해 최초 실행 파일 선택창에서 가져옵니다.
- `licenses.db`와 이전 개인키가 모두 없으면 고정된 TMS 검증 공개키에 대응하는 개인키를 복구할 수 없으므로 라이선스를 발급할 수 없습니다. 관리자 DB는 반드시 암호화된 별도 매체에 백업하세요.

## 발급 절차

1. TMS 라이선스 화면에서 `.tmshw` 하드웨어 키 파일을 저장합니다.
2. 관리자 계정에서 공용 업데이트 토큰을 한 번 설정한 뒤 `.tmshw` 파일을 불러옵니다.
3. 고객, 영화관, 사용 기간과 허용 상영관 수를 입력하고 `.tmslic` 파일을 발급합니다.
4. 발급된 `.tmslic` 파일을 해당 TMS에 등록합니다.

발급 이력에는 신규 발급·갱신 구분, 처리한 로그인 계정, 처리 일시와 상영관 한도가 표시됩니다. 기존 제한 없는 라이선스를 갱신할 때는 1개 이상의 상영관 한도를 새로 지정해야 합니다.

`data\licenses.db`에는 암호화된 개인키와 계정·발급·감사 기록이 함께 들어 있습니다. DB와 관리자 계정 비밀번호를 모두 잃으면 새 라이선스를 발급할 수 없으므로 DB는 암호화된 별도 매체에도 백업하고 관리자 비밀번호는 별도로 안전하게 관리하세요. 신뢰할 수 있는 암호화 클라우드로 프로젝트 폴더를 공유할 수 있지만, 관리자를 완전히 종료하고 동기화가 끝난 뒤 다른 PC에서 실행해야 하며 두 PC에서 동시에 열면 안 됩니다.

## 오프라인 프로그램 업데이트

관리자 계정으로 로그인한 뒤 상단 `온라인 업데이트`로 비공개 GitHub Release를 확인하거나, `파일 업데이트`에서 `Cinema-TMS-Admin-Update-*.zip`을 선택합니다. `data\licenses.db`, 계정, 발급키, 공용 토큰과 이력은 유지되며 프로그램 파일만 교체됩니다. 변경 전 파일은 `data\update-backups`에 백업되고 실패 시 자동 복원됩니다.

공용 토큰은 `data\github-update-token.dpapi`에 현재 Windows 사용자 범위로 암호화되며 설치 ZIP과 Git에는 포함되지 않습니다. 최신 `.tmshw`를 불러와 발급한 라이선스에는 해당 TMS 장비만 복호화할 수 있도록 다시 암호화되어 자동 업데이트에 사용됩니다.
